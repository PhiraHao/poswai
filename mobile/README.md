# แอป POS WAI (แอนดรอยด์ · ไอโฟน)

แอปจริง ไม่ใช่เปลือกที่เปิดเว็บ **หน้าจอทั้งหมดอยู่ในเครื่อง** คุยกับเซิร์ฟเวอร์ของร้านแค่ข้อมูล
เปิดแอปติดทันทีไม่มีจอขาวรอโหลด · เน็ตหลุดยังใช้ได้ · พิมพ์ใบเสร็จ Bluetooth ตรงจากแอป

> ของเดิมที่โฟลเดอร์ `app/` เป็นเปลือกที่ชี้ไป `poswai.zzaxstudio.com` — เลิกใช้แล้ว
> เพราะ Google ไม่ยอมให้ล็อกอินในเว็บวิวของแอป และมันไม่ได้ทำงานตอนเน็ตหลุด

## คำสั่งที่ใช้

ทีละบรรทัด (เทอร์มินัลเป็น PowerShell 5.1 ใช้ `&&` ไม่ได้)

```bash
cd mobile
```
```bash
npm install
```
```bash
npm run sync
```

`npm run sync` = สร้าง `www/` ใหม่จากหน้าเว็บข้าง ๆ แล้วส่งเข้าโครงเนทีฟ
**ทุกครั้งที่แก้หน้าเว็บ ต้องรันอันนี้ก่อน build** ไม่งั้นแอปยังเป็นของเก่า

สร้าง APK:

```bash
cd mobile/android
```
```bash
$env:JAVA_HOME = "C:/Program Files/Android/Android Studio/jbr"
```
```bash
./gradlew assembleDebug
```

ไฟล์ออกที่ `mobile/android/app/build/outputs/apk/debug/app-debug.apk`

ติดตั้งลงมือถือที่เสียบอยู่:

```bash
C:/Users/phira/AppData/Local/Android/Sdk/platform-tools/adb.exe install -r mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

## แหล่งเดียว ไม่มีสองสำเนา

`www/` **สร้างอัตโนมัติ ห้ามแก้ไฟล์ในนั้น** — `build-www.mjs` คัดลอกจากหน้าเว็บจริง
ที่อยู่โฟลเดอร์แม่ แล้วแก้ 3 อย่างที่หน้าเว็บสมมติว่ามีเซิร์ฟเวอร์เสิร์ฟ:

1. ใส่ `app-bridge.js` เป็นสคริปต์ตัวแรกของหน้า
2. ตัด `?v=NN` ท้ายชื่อไฟล์ (กันแคชของเซิร์ฟเวอร์ ในแอปไม่ต้องใช้)
3. ปิด service worker (แอปมีไฟล์อยู่แล้ว เพิ่มชั้นแคชไปก็มีแต่ของเก่ากว่า)

รายชื่อไฟล์ที่ต้องเอาไปด้วย **อ่านจาก `index.html` เอง** ไม่ได้เขียนรายชื่อไว้
เพราะรายชื่อจะล้าสมัยทันทีที่มีคนเพิ่มหน้าใหม่ และมันจะพังตอนที่ร้านเปิดขายอยู่แล้ว

## สะพาน (`src/app-bridge.js`)

สิ่งเดียวที่เขียนขึ้นใหม่เพื่อแอป ที่เหลือคือหน้าเว็บเดิมทั้งหมด

- **เส้นทาง** `/api/…`, `/menu-photos/…`, `/t/…` ชี้ไปเซิร์ฟเวอร์ของร้าน ที่เหลือคือไฟล์ในเครื่อง
- **บัตรผ่าน** เว็บเก็บเซสชันในคุกกี้ httponly แอปทำไม่ได้ (ไอโฟนปฏิเสธคุกกี้ข้ามเว็บ)
  แอปจึงเก็บโทเคนเองแล้วแนบไปใน header ทุกครั้ง
- **ล็อกอิน** เปิด**แท็บเบราว์เซอร์จริง** ไปหน้า Google/LINE (เป็นวิธีเดียวที่ Google อนุญาต)
  เซิร์ฟเวอร์ส่งเซสชันกลับมาทาง `poswai://auth` ซึ่งมีแต่แอปนี้ตอบ
- **รูปเมนู** หน้าเว็บใส่ path ของเซิร์ฟเวอร์ลง `<img>` ตรง ๆ หลายที่ สะพานไม่ไปตามแก้ทุกจุด
  แต่ดักตอนรูปโหลดไม่ขึ้นแล้วไปขอจากเซิร์ฟเวอร์ให้ (รูปในเครื่องไม่เคยเข้าทางนี้)
- **จอไม่ดับ** ขณะแอปอยู่หน้าจอ และปล่อยทันทีที่ออก (ไม่ค้างจอตอนอยู่ในกระเป๋า)

ชี้ไปเซิร์ฟเวอร์อื่นตอนทดสอบ: เปิด DevTools ของเว็บวิวแล้วสั่ง

```js
localStorage.setItem('poswai.app.server', 'http://192.168.1.50:8000')
```

## ฝั่งเซิร์ฟเวอร์ที่คู่กัน

`poswai_mobile.py` + เทสต์ `test_app_session.py` (รัน `python -m unittest test_app_session`)

- `require_staff` และเซสชันเจ้าของ รับโทเคนจาก header `x-poswai-session` / `x-poswai-owner`
  ได้ด้วย ไม่ใช่แค่คุกกี้ — **เว็บยังทำงานเหมือนเดิมทุกอย่าง** มีเทสต์ยืนยันทั้งสองทาง
- `/api/owner/auth/{provider}/start?app=1` จำไว้ว่าเป็นการล็อกอินจากแอป แล้วตอน callback
  ส่งกลับไป `poswai://auth?owner=…` แทนที่จะวางคุกกี้
- **ไม่ต้องแก้คอนโซล Google หรือ LINE เลย** redirect URI ยังเป็นของเซิร์ฟเวอร์ตัวเดิม
  การกระโดดเข้า `poswai://` เกิดจากเซิร์ฟเวอร์เรา ไม่ใช่จาก Google

## หน้าตาแอป (`src/app-shell.css` + `src/app-shell.js`)

หน้าเว็บบนมือถือมีสไตล์ 4 ไฟล์แย่งกันคุม (ui, workspace, redesign หลายตัว) วัดบนมือถือจริงแล้ว
ใช้ขนาดตัวอักษรปนกัน 14 ขนาด ชั้นนี้โหลดหลังสุดและ**ใช้เฉพาะในแอป** (ทุกกฎอยู่ใต้
`html.poswai-app` ซึ่งมีแต่สะพานของแอปที่ใส่ให้) เว็บไม่โดนกระทบเลย

- **ตัวอักษร 5 ขนาดเท่านั้น** 12 · 14 · 16 · 18 · 22 กฎเขียนตาม "บทบาท" (ตัวเลขสรุป ป้าย หัวการ์ด
  ปุ่ม ป้ายสถานะ ตาราง แท็บย่อย) ไม่ใช่ตามหน้า หน้าใหม่ที่ใช้ชิ้นส่วนเดิมจะเข้าระบบเอง
- **ปุ่มกดได้สูง ≥44px** ทุกปุ่มในหน้าจอ
- **หัวจอ** โลโก้ · สาขา (กินที่ที่เหลือ ตัดด้วย …) · จุดออนไลน์ (สถานะ ไม่ใช่สวิตช์) · ภาษา · วงกลมชื่อย่อ
  ยังไม่ล็อกอินเป็นปุ่มเหลือง "เข้าสู่ระบบ"
- **แถบล่าง** 5 ช่องเท่ากัน · 4 แท็บแรกที่ตำแหน่งนี้เปิดได้จริง + เพิ่มเติม (เลือกจากสิทธิ์ ไม่ใช่ลำดับ)
- **แผ่นเพิ่มเติม** เลื่อนขึ้นจากล่าง แสดงเฉพาะแท็บที่ล้น · ปุ่มย้อนกลับแอนดรอยด์ปิดแผ่นก่อน
- **ตารางเมนู/สต็อก** กลายเป็นการ์ดทีละรายการ ตัวเลขสต็อกมีป้ายกำกับในตัว

ตรวจซ้ำได้ด้วยการวัด: ต่อ DevTools เข้าเว็บวิว (`adb forward tcp:9333 localabstract:webview_devtools_remote_<pid>`)
แล้วนับขนาดตัวอักษรที่ไม่อยู่ใน 12/14/16/18/22 และปุ่มที่เล็กกว่า 44px — รอบนี้ได้ 0 ทุกหน้า

**กับดัก** ทดสอบลิงก์ `poswai://auth?...&...` ผ่าน `adb shell am start` ต้องครอบลิงก์ด้วย `'…'` ข้างใน
คำสั่ง shell ไม่งั้นเชลล์ในมือถือตัดที่ `&` แอปจะได้ลิงก์ไม่ครบแล้วขึ้นหน้าเลือกร้านแทน

## กับดักที่เคยเจอมาแล้ว

- `@capacitor/keep-awake` **ไม่มีจริง** ตัวจริงคือ `@capacitor-community/keep-awake`

  สะพานเก็บคีย์ใน `localStorage` เพราะคำขอแรกเกิดก่อนที่การอ่านแบบ async จะเสร็จ)
- `android/local.properties` ต้อง escape โคลอน: `sdk.dir=C\:/Users/phira/AppData/Local/Android/Sdk`
  ไม่งั้น gradle ขึ้น Invalid file path
- Capacitor รุ่นปัจจุบันคือ 8

## ไอโฟน

โค้ดรองรับไอโฟนครบแล้ว (`capacitor.config.json` มีส่วน `ios` · POS58 มี BLE ไอโฟนคุยได้)
แต่ **build ไอโฟนต้องใช้เครื่อง Mac และบัญชีนักพัฒนา Apple 3,500฿/ปี** ซึ่งยังไม่มี
วันไหนพร้อม สั่ง `npx cap add ios` บน Mac ได้เลย ไม่ต้องแก้โค้ดอะไร
